# redact

Disclaimer: This project is almost entirely AI generated by Claude Code.

Keep private values out of a public git repository while your working tree keeps them.

Your NixOS config, dotfiles or infrastructure repo can be public and still hold your
username, password hash, email addresses and ssh hosts. On disk the files hold the
real values, so your tools read them as usual. In git they only ever hold
`REDACTED[NAME]` tokens, so anyone reading the public repository can see at a
glance where a value was withheld.

- **Git does the work.** Files marked `filter=redact` in `.gitattributes` go through
  a git clean/smudge filter. `git add`, `diff`, `stash`, `checkout`, `reset`,
  `pull` and `rebase` all just work, and nothing can be staged untokenised.
- **One encrypted store.** Values live in `.redact/secrets.age`, encrypted with
  [age](https://age-encryption.org) (post-quantum by default) to the recipients in
  `.redact/recipients`. The store is committed and is useless without an identity.
- **Fails closed.** If the store can't be read, the clean filter refuses and
  `git add` fails. The smudge filter leaves tokens in place, so checkouts still
  work without a key.
- **A leak scanner.** `redact check` looks for stored values (current, retired and
  previously seen ones) plus well-known secret shapes. It scans the working tree,
  the index (the pre-commit hook) or the whole history.

## Install

With Nix:

```sh
nix profile install github:scuba-plaza/redact
```

or as a flake input:

```nix
inputs.redact.url = "github:scuba-plaza/redact";
inputs.redact.inputs.nixpkgs.follows = "nixpkgs";
# home.packages = [ inputs.redact.packages.${pkgs.system}.default ];
```

With Go 1.26 or later:

```sh
go install github.com/scuba-plaza/redact/cmd/redact@latest
```

`redact` has to be on `PATH`, because git runs it as a filter and from the hooks.
It runs on Linux and macOS and needs git 2.32 or later.

## Quick start

In a new repository:

```sh
redact init                          # identity (if you have none), .redact/, filter, hooks
redact set SYS_USER                  # hidden prompt; or: printf alice | redact set SYS_USER
redact set SSH_CONFIG < ~/ssh.extra  # multi-line values come from stdin
redact add local/settings.nix        # mark it redacted and stage it tokenised
git commit -m "Redact local settings" # the pre-commit hook scans the index
```

`redact add` writes `/local/settings.nix filter=redact` to `.gitattributes` and stages
both. Put `REDACTED[NAME]` tokens into a file yourself, or let the filter replace
stored values with their tokens.

In a fresh clone, copy your identity over first, then:

```sh
redact init            # configures the filter, merge driver and hooks, then hydrates
```

Without an identity, `init` still configures the filter and the hooks before it
stops, so git refuses to stage redacted files until the identity is in place.

`init` is idempotent, so run it whenever you are unsure. `redact status` tells you
what, if anything, is wrong.

## Commands

| command | what it does |
|---|---|
| `redact init` | Set up the repository and this clone, then hydrate. `--classic` generates an X25519 identity instead of a post-quantum one. `--force-hooks` replaces hooks that redact did not write. |
| `redact set NAME` | Store a value from stdin (trailing newlines trimmed) or a hidden prompt. The old value is retired, and redacted files are rehydrated. |
| `redact get NAME` | Print a value. |
| `redact edit NAME` | Edit a value in `$VISUAL`/`$EDITOR`. The temp file is created in `$XDG_RUNTIME_DIR`, mode 0600, and removed afterwards, even if you press Ctrl-C. Nothing is saved if the value changed while you were editing. |
| `redact unset NAME` | Remove a value. The token comes back in the files. `--forget` also drops the retired values and this clone's memory of them. |
| `redact list` | Every name, whether it has a value, how many retired values it has, and which files use it. |
| `redact add PATH...` | Redact files: add them to `.gitattributes` and stage them through the filter. Warns if `HEAD` already holds their real values. |
| `redact hydrate` | Bring every redacted file up to date with the store. It keeps your edits and prompts for missing values on a terminal. |
| `redact status` | Check the identity, store, recipients, filter, hooks and every redacted file. Exits 1 if anything needs attention. |
| `redact check` | Scan for leaks. `--staged` scans the index, `--history` scans every blob reachable from any ref, `--json` prints machine-readable output, `--reveal` prints matches unmasked, `--no-values` scans without the store. |
| `redact rekey` | Re-encrypt the store to the current `.redact/recipients`, show who was added or removed, and trust that list in this clone. The only command that changes who can read the store. |
| `redact completion SHELL` | Shell completions for bash, zsh, fish and PowerShell. |

Global flags:
- `-C DIR` runs as if redact had been started in `DIR`.
- `--identity FILE` picks the identity.
- `--no-color` disables colour; `NO_COLOR` is honoured too.

Exit status:

| code | meaning |
|---|---|
| 0 | success |
| 1 | findings, an unhealthy `status`, values `hydrate` could not fill, or a refused action |
| 2 | usage or operational errors |

## Values

Names look like `SYS_USER`: capital letters, digits and underscores, starting with a
letter. In files they appear as `REDACTED[SYS_USER]`. That works inside Nix, TOML
and JSON strings, unquoted as a block-style YAML value, and as a whole line in an
ssh config. Quote it inside YAML flow collections (`[...]`, `{...}`), where `[` and
`]` have a meaning of their own.

A value must be at least 3 bytes of UTF-8 and must not contain `REDACTED[`.
Anything else goes, including `@handles`, emails and brackets. Two names cannot
hold the same value.

The clean filter commits the tokenised form of the file *as a checkout would
show it*: markers that have a value are hydrated first, then every stored value
is replaced in one pass, longest first. So `alice@REDACTED[DOMAIN]` is committed
as `REDACTED[EMAIL]` when that is what it reads as after a checkout, and what git
stores never changes on the next checkout. It refuses, naming the line and column
in your file, if:
- a stored value runs into a marker
- a value would form a new marker with the text around it
- two stored values overlap, so hiding one would leave part of the other in clear

A misspelt marker such as `REDACTED[sys_user]` is never hydrated. `hydrate`, `add`
and `status` warn about it with its line number. It is only a warning, because a
literal like `REDACTED[%s]` can be legitimate.

**Retired values.** When `set` replaces a value or `unset` removes one, the old
value is kept as a *retired* value of the same name. Retired values are still
tokenised, so a working tree hydrated with the old value never leaks it after a
`git pull`, and `check` still looks for them, because a rotated secret is still
private. `unset --forget` drops them.

**Values seen before.** Each clone also keeps every value it has seen in
`.git/redact/known.age`, encrypted to your own identity. If the store moves
*backwards* (`git reset --hard`, an older branch, a rebase), the newer values it
no longer knows are still tokenised and scanned for. Without this, the newest
secret would be the one to leak.

## Identities and recipients

Your identity is looked up in this order:
1. `--identity`
2. `$REDACT_IDENTITY`
3. `git config redact.identity` (`~` is expanded; relative paths start at the repository root)
4. `~/.config/redact/identity.txt`

`redact init` generates a post-quantum (ML-KEM-768 + X25519) identity if you have
none. Back it up: it is the only way to read your store.

Identity files can hold age identities (`AGE-SECRET-KEY-…`) or an unencrypted
ed25519 or RSA SSH private key. `.redact/recipients` uses age's recipients file
format: one `age1…`, `age1pq1…`, `ssh-ed25519 …` or `ssh-rsa …` per line, with
`#` comments allowed. age refuses to mix post-quantum and classic recipients.

To share the store with a second machine or person:

```sh
echo age1pq1… >> .redact/recipients   # their public key
redact rekey                          # prints "+ age1pq1…"
git commit -m "Add a recipient" .redact
```

Only `rekey` reads `.redact/recipients`. Every other write encrypts to the
recipients recorded inside the store itself, so a key slipped into the file
(through a pull request, say) gains nothing until you review it and run `rekey`.
`status` reports any difference between the file and the store.

Each clone also remembers which recipients it trusts. It trusts the store's list
on its first `init`, and after that only through `rekey`. If someone replaces
`.redact/secrets.age` with a store encrypted to an extra key, your next write is
refused instead of handing them your values.

A write is also refused if your own identity could not read the result. Removing
a recipient does not take back what they could already read, so rotate those
values.

**Merging.** `init` registers a merge driver for `.redact/secrets.age`. When two
machines change the store, a merge decrypts all three versions:
- names changed on only one side merge cleanly
- a name changed differently on both sides keeps your value, retires theirs and
  reports a conflict; settle it with `redact set NAME` and
  `git add .redact/secrets.age`
- recipients merge the same way, but must already be trusted in this clone

## Checking for leaks

`redact check` reports:

- stored values, retired values and values this clone has seen before
- private key blocks and age identities
- crypt password hashes (`$6$`, `$y$`, `$2b$`, …) and SCRAM verifiers
- GitHub, AWS, Slack, Google and Anthropic API tokens
- hardcoded `/home/<name>/` and `/Users/<name>/` paths
- numeric GitHub noreply addresses
- email addresses, except reserved domains such as `example.com`, `*.invalid` and `*.test`
- public IPv4 addresses, except private, reserved and documentation ranges, and well-known public resolvers
- UUIDs

Inside redacted files a value matches anywhere. Elsewhere, values shorter than
12 bytes only match as a whole word, so `alice` does not fire on `malice`. For
multi-line values, every line of 8 or more characters is searched for on its own.
Binary files (a NUL byte in the first 8000 bytes, as git decides) are searched
only for stored values of 8 bytes or more, both as UTF-8 and as UTF-16. Shorter
values would match random bytes in images and archives.

The default mode scans redacted files *as they would be committed*. `--staged`
scans the index using the index's `.gitattributes`, and is what the pre-commit
hook runs. `--history` scans every blob once, under every path it was committed
at, and names the commit that introduced it. It uses today's `.gitattributes`.
Matches are masked (`ali… (16 chars)`) unless you pass `--reveal`.

To silence a false positive:

```gitattributes
# .gitattributes: skip paths entirely
docs/** -redact-scan
```

```
# .redact/allow: one regular expression per line, matched against the whole finding
.*@mycompany\.example
```

In CI, where there is no identity, run `redact check --history --no-values`.
Without the store, redacted files are scanned as they are on disk.

## Hooks

`redact init` installs three hooks into `.git/hooks`. It updates hooks it wrote
earlier, and never overwrites another hook unless you pass `--force-hooks`.

| hook | runs |
|---|---|
| pre-commit | `redact check --staged`, and fails closed if `redact` is not on `PATH` |
| post-checkout, post-merge | `redact hydrate --no-prompt --quiet`, so pulls and branch switches bring in new values |

If `core.hooksPath` is set, redact does not write there. It prints the line to
add to each hook instead, and `status` reports the hooks as not managed.

Atomic writes go through `.<name>.redact-tmp-*` files next to the target. `init`
lists that pattern in `.git/info/exclude`, so a write interrupted by a crash
cannot be staged by `git add -A`.

## Using it with a Nix flake

Nix's git fetcher reads tracked files from the working tree, so a flake referenced
as `.#host` evaluates the hydrated values. The tree stays clean, because the
clean filter maps them back to the committed tokens.

- **Stale evaluation cache.** Nix caches evaluations of a clean tree by commit, not
  by content. After a value changes it can keep building the old value. redact runs
  `git config redact.postHydrate` after every hydration that changed a file:

  ```sh
  git config redact.postHydrate 'rm -rf "${XDG_CACHE_HOME:-$HOME/.cache}"/nix/eval-cache-v*'
  ```

- **Unhydrated files.** To stop evaluation while a file still holds tokens, check
  for them in `flake.nix`:

  ```nix
  tokenLike = s: builtins.match ".*REDACTED\\[[A-Z][A-Z0-9_]*].*" s != null;
  ```

- **World-readable store.** Nix copies the hydrated files into `/nix/store`, which
  every local user can read. Don't store values that local users must not see.

- **Configure the filter globally.** You can set the filter in your global git
  config (for example from home-manager). Clones of any repository using it are
  then hydrated as they are checked out:

  ```nix
  programs.git.settings.filter.redact = {
    clean = "redact clean -- %f";
    smudge = "redact smudge -- %f";
    required = true;
  };
  ```

## Moving from `bin/redact`

There is no compatibility layer. Move a repository over once:

```sh
age -d -i ~/.config/age/key.txt secrets.age   # read the old values one last time
git rm bin/redact .redacted secrets.age scripts/install-hooks.sh
sed -i 's/@@\([A-Z][A-Z0-9_]*\)@@/REDACTED[\1]/g' local/settings.nix local/ssh.conf
redact init
redact set SYS_USER                           # ...once per value
redact add local/settings.nix local/ssh.conf
redact hydrate
git commit -m "Switch to redact"
```

Point `home/local-bin.nix` at the flake package instead of `../bin/redact`, change
the `tokenLike` check in `flake.nix` to the pattern above, and replace
`scripts/install-hooks.sh` with `redact init`.

## What redact does not do

- It cannot know about a private value you never stored. The shape rules catch
  common cases; everything else is up to the store.
- It does not rewrite history. If a value was committed before, `redact add`
  and `redact check --history` tell you; rotate it or rewrite history yourself.
- Tools that commit without the git CLI (for example libgit2-based GUIs) skip both
  the filter and the hooks.
